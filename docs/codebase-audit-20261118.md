# 代码结构与清理记录（2026-11-18）

本次检查针对本机工作区。`server.js` 约 4,200 行，`public/app.js` 约 4,100 行，是目前最值得拆分的两个入口。

| 路径 | 职责 |
|---|---|
| `server.js` | HTTP 路由、静态资源、服务组装，以及部分采集任务和缓存逻辑 |
| `server/background-worker.js` | 本地后台 HTTP 入口，处理录像分析和弹幕任务 |
| `server/services/` | 玩家资料、实时对局、录像、赛事、媒体、缓存和上游请求控制 |
| `public/` | 页面入口和共享脚本、样式。民族统计、科技树、赛事结果、录像地图已有独立模块 |
| `public/assets/`、`public/tech-tree-data/`、`public/guess/` | 静态资源、生成数据、猜玩家页面 |
| `config/`、`map/` | 直播及视频配置、实时检测池、账号关联、游戏数据补充配置 |
| `scripts/` | 定时刷新实时对局检测池，通过 systemd 调用 |
| `tools/` | 数据构建与导入、一次性修订、自动测试及 Nginx/systemd 等运维配置 |
| `.cache/`、`.codex-tmp/`、`output/` | 运行数据及备份、开发临时产物、导出文件 |

## 建议的重构顺序

1. **提取玩家资料与对局路由。** 把 `server.js` 中 `/api/profile-*` 的请求解析和响应组装迁到独立路由模块，与现有资料、对局服务组合。分页测试随后可直接调用处理器，避免用字符串截取源码和 `vm` 手工补齐运行依赖。
2. **按页面拆前端。** 从玩家资料和实时对局着手，把页面状态、轮询、渲染和离开页面时的清理放在同一个模块内。`public/app.js` 保留站点导航和共享入口。先复用已有页面模块的动态加载方式，再逐步迁移相关样式。
3. **收拢媒体任务与缓存。** 将直播轮询、视频采集和缓存持久化从网站入口提取成独立服务，复用现有请求控制。明确每个缓存的写入者和失败后的旧数据处理。把调度迁往后台进程前，先确认只有一个实例写入。
4. **给工具目录建立入口清单。** 列出定时任务、人工运维命令、可重复生成脚本和历史数据迁移。先核对部署路径与 systemd 引用，再移动文件。临时诊断日志可按批次清理，源码归档、业务缓存和原图分别保留和管理。
