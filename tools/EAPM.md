# 本站 eAPM 统计口径

- 时间单位为录像的游戏毫秒；全局值为有效指令数 / 游戏分钟，不再乘游戏速度。
- 只计入 `[0, 对局时长]` 内、属于已知玩家的有限时间戳。统计前按时间排序，网页玩家表、动态图表和结束摘要共用 `public/replay-eapm.js`。
- 当前值为 `(当前时间 - 60 秒, 当前时间]` 内的操作数，开局不足一分钟时显示累计数量；最高值为任意连续 60 秒窗口的最高操作数。
- 所有白名单指令统一执行严格的重复过滤，包括生产、研究、交易、变形及切换。对每个玩家、每种类型和含义相同参数的指令，分别记录最近一次出现时间；间隔不超过 500 现实毫秒（乘录像游戏速度换算为游戏毫秒，正常 1.7 倍速为 850 游戏毫秒）时合并，每次收到重复指令仍推进时间边界。
- 穿插其他指令不会重置这个指令的窗口，因此 ABAB、ABCABC 和更多不同指令组成的循环适用同一规则。不同玩家互不影响；每个玩家最多保留最近 256 个指令参数组合。
- 目标、坐标、数量等参数不同仍分别计数，对象字段顺序不影响比较。一次批量生产命令计一次操作，不按单位数量加权。
- 白名单对照 [aoe2rec ActionData](https://docs.rs/aoe2rec/latest/aoe2rec/actions/enum.ActionData.html) 核对并补充停止、路点、跟随、守卫、修理、旧生产队列等已知玩家指令；AI 指令、未知包、保存、投降和系统记录不计入。
- 500 现实毫秒（乘录像游戏速度换算为游戏毫秒，正常 1.7 倍速为 850 游戏毫秒）是用户指定的严格去重阈值，不是引擎标准；快速真实重复下单也会合并。录像指令不能充分证明执行成功或经济收益，因此本站统计不承诺与 CaptureAge / AoE2 Insights 完全一致，也不据此评定玩家水平。

验证使用模拟指令和本地缓存录像，不发送测试弹幕。回归测试：`node --test tools/test-replay-eapm.mjs tools/test-replay-ended.mjs tools/test-replay-job-frontend.mjs`。

- 游戏速度优先读取录像设置 speed，然后读取录像头 game_speed / replay.game_speed；缺少有效信息时按 DE 正常 1.7 倍速处理。时间窗依据录制时游戏速度，和网页播放倍速无关。

- 纯空白点击、选中单位和切换画面属于界面输入，不在有效指令白名单内，反复操作不会增加 eAPM。当前不对它们额外虚构第一次操作；现有录像接口无法完整还原所有玩家的鼠标、镜头输入。若空地点击实际下达了移动指令，则按该游戏指令执行现实 500ms 重复去重。

- 语义比较：只对 unit_ids / building_ids / object_ids 这些执行对象集合排序；剔除包长度 action_length，以及已由完整非空对象列表确定的 selected 数量。目标、精确坐标、生产数量、科技、资源、模式和其他有效参数保持区分。负数 selected 表示复用选择，不能当作空集合忽略。
- 部分指令尚未解码，data 原始字节数组和 unknown 字段可能携带目标、模式或坐标，因此保留其内容和顺序，不武断删除。当前语义归一化只应用于已确认结构，不能完全消除这些未解码字段的差异。
