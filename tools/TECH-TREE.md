# 民族科技树

入口 `/tech-tree`，由现有 SPA 导航加载 `public/tech-tree.js`。数据全在本站，浏览时不请求第三方资料或图标。

## 数据来源与口径

- [SiegeEngineers/aoe2techtree](https://github.com/SiegeEngineers/aoe2techtree)，固定提交 `3bb43b1439eef88dfe7fe892d7f7dc41ac9dd76f`，2026-09-22，游戏更新 **185872**。
- 使用该版 `data/data.json`、`data/locales/zh/strings.json`、`data/trees/*.json` 和相关 `img/` 图标；只收录 `era=base` 的决定版民族。
- 当前 56 个民族、248 种单位、39 种建筑、199 项科技、433 个图标。数量指科技树导出中的不同游戏 ID，包含升级形态，不包含全部战役/编辑器对象。
- 可用性以各民族原始树的 `node_status` 为准；时代和前置关系来自节点字段，不从图标位置猜测。原始数据未指定的前置条件不补造连线。
- 数值面板显示基础数值，**不计算**民族加成、科技叠加和模式修正；这些限制在页面和详情中明确显示。民族特性显示游戏中文文本。
- 节点名称使用 `name_string_id`，详情使用 `help_string_id - 79000`，不同于数值对象的 `LanguageNameId`。移除原始 HTML 和游戏运行时占位符，渲染时继续转义文本。
- 图标/游戏文本版权属于相应权利人；随页面保留 `public/tech-tree-data/NOTICE.txt` 和上游 MIT 许可证，不表示微软背书。

## 更新

1. 检查上游提交及对应游戏版本。修改构建器中的固定提交和版本元数据；不能只换页面版本号。
2. 下载并解压该提交的仓库 ZIP。
3. `python tools/build-tech-tree.py --source-dir <解压目录>`，会重建 `public/tech-tree-data/`，复制所需图标到 `public/assets/tech-tree/`。
4. 检查新旧民族/对象差异。上游删除对象时，人工确认是否清理旧输出，不把旧文件当成新版本引用。
5. 更新 `public/tech-tree.js` 的 `datasetVersion` 及 HTML/CSS/模块资源版本，避免混用缓存。
6. 验证后部署生成的数据、图标、模块、CSS、`index.html`、路由变更。无每周自动改动游戏资料的任务；民族胜率统计的周更新和游戏科技树数据互相独立。

## 验证

- `node --test tools/test-tech-tree.mjs`：全部民族实体/图标/时代/前置引用、民族可用性、升级关系、组合搜索和显示文本检查。
- `node tools/check-tech-tree-browser.mjs`：实际 SPA 页面、详情、不可用筛选、民族切换、双语搜索、手机/桌面布局、模块往返、深链接和图标无 404。需要 Playwright Chromium；只使用隔离静态测试服务，不调用线上业务 API。截图在忽略目录 `.cache/qa/`。
- `node --test tools/test*.mjs`：已有服务回归测试。浏览器检查单独执行，不要求生产服务器安装测试用浏览器。

深链接示例：`/tech-tree?civ=chinese&node=Unit_24_87`。民族切换使用请求序号，迟到的响应不能覆盖较新的选择。

PC端科技树画布支持按住鼠标左键横向拖动。移动达到6px才开始拖拽，拖拽结束抑制该次点击，避免误打开节点详情；正常点击、触屏原生滑动及键盘浏览保持可用。按用户要求隐藏画布底部原生滚动条，不再提供可用鼠标直接拖动的滑块。

民族加成文本如果在原始数据中途换行，而续行没有新项目圆点，则视为上一条加成的延续。马里的兵营单位远程护甲加成等七处不会产生第二个圆点；PC端民族加成列在宽屏加宽，较窄桌面改用两列布局，确保马里整项在一行显示。原始科技树资料保留上游文本。

## 攻防名称与排布（2026-10-26）

`public/tech-tree-classes.js` 的主要类别名直接核对本机游戏 `resources/zh/strings/key-value/key-value-strings-utf8.txt` 中 12400+类别 ID 的原始文本（Steam build 25464265）。例如 2=主力舰、29=冲击步兵、37=重型攻城武器、39=龙脉、41=喷火船、60=远程战船；不能用旧表把它们替换成龟船、鹰勇士或未使用字段。

游戏把 0、31、40 标为未使用，但导出数据仍在奇观、普通对象、房屋/木栅栏上保留这些字段。界面为它们提供带“保留”说明的具体名称；旧利提斯和火药副弹丸含义交叉核对 [AoE2ScenarioParser DamageClass](https://ksneijders.github.io/AoE2ScenarioParser/api/AoE2ScenarioParser/datasets/trigger_lists/damage_class.html)，不把保留字段解释为当前额外减伤。测试遍历数据中的全部攻击/护甲条目，要求均有具体名称。

费用统一按 Wood、Food、Gold、Stone 输出。详情不再显示可用民族。科技树必须保留原始 `row` / `column`，船坞按实际列数展开，不能按时代把项目重新自动挤入四列。建筑在标题名称后展示图标，不再占重复的时代节点；单位的原始列保持不变，防止独立升级路线重叠。民族特色默认展开，可收起；四时代行距缩小。

民族标题中只显示独特单位图标，可点击详情。按特色单位标记和父子关系，每条单位线仅展示一次，去掉精锐重复形态；区域单位不混入独特单位（中国为龙舟、诸葛弩）。

后续展示调整：民族标题中的独特单位改为无边框大图，铺满中间展示区域，保留完整比例及点击详情。大图来自本机游戏 `widgetui/textures/ingame/units` 的原始 256×256 DDS，通过 `python tools/export-tech-tree-portraits.py --game-dir <AoE2DE>` 仅转换为 WebP，输出到 `public/assets/tech-tree/portraits/`，不放大科技树小图。游戏素材仍适用既有版权声明。详情存在“升级至该单位”时，该栏排在训练费用等信息之前。

玩家配色现已在构建阶段固定，详见下方“固定配色与缓存”。旧运行时着色模块仅保留给旧页面与构建验证。

民族统计的民族表现与对位列表名称改为对应 `/tech-tree?civ=<slug>` 的常规链接，可正常使用浏览器返回、在新标签页打开；统计对位筛选继续由下拉框操作。


民族特色与团队加成默认展开，切换民族保持展开。建造、训练、研究时间与对应费用同一行靠右显示，不在基础属性中重复。

当前已弃用运行时深色阈值去底，统一使用 `public/assets/tech-tree/portraits-png/*.png`（148 张真正 RGBA 透明 PNG）。`tools/build-transparent-portraits.py` 从原始纹理批量构建；`config/tech-tree-portrait-mattes.json` 保存五张带金色背幕/火光的单独复核轮廓。运行时只读取 PNG 的既定透明度，并使用原始玩家色遮罩换色，不再根据人物深浅猜测背景。旧 WebP 保留供旧版本缓存引用。导航顺序为“视频直播 → 居中短实线 → 民族统计 → 民族科技树”。

建筑类别覆盖全部 39 种建筑，未知建筑使构建失败；大庄园（1734）、大商站（1021）、商队旅馆（1754）、牧场（1889）、聚落（2556）明确归经济类。

透明 PNG 构建依赖 Pillow、NumPy。命令：`python tools/build-transparent-portraits.py`，随后执行 `node tools/check-tech-tree-browser.mjs`。后者生成全部图片的四张浅底检查总览及波兰单位回归截图。游戏原图本来就在 256×256 画框内被截断的身体/装备不会被补画。

## 固定配色与缓存（2026-10-26）

顶部独特单位额外包含游戏树未标 `unique` 的瓦兰吉卫队（2703）与雄鹰战士（753）；神庙护卫沿用原标记。肖像导出与固定配色构建器使用同一补充名单。游戏数据 185872 链接指向本站更新汇总文章 53155105。民族图标下的整体胜率读取 `/api/civilization-stats/winrates`，分别按 1v1 的 1950 和 TG 的 1650 分成低/高档，按胜场与出场数汇总；统计库每周替换后接口自动按数据库修改时间重载。页面初次进入、重新进入、重新获得焦点和持续停留时每5分钟读取；仅统计结果变化才重绘。

`config/tech-tree-portrait-colors.json` 保存每个民族一次随机选定的玩家颜色（1、2、3、4、5、6、8，排除灰色），中国固定4号黄色。同民族全部特色单位使用同一颜色，重建时保留已有分配。

`python tools/build-fixed-portraits.py` 从原始 RGBA 玩家色遮罩和已复核透明 PNG 轮廓生成149张成品，输出 `public/assets/tech-tree/portraits-fixed/<civ>/*.png`，同时生成 `public/tech-tree-fixed-portraits.js`。包含升级形态；标题仍按原有规则每条单位线显示一次。透明度逐像素验证不变。修改素材时递增构建器中的 portraitAssetVersion 并更新模块引用版本。

页面直接加载固定配色的透明 PNG，不再请求原始 RGBA、配色纹理或在浏览器中着色。成品 PNG 使用 `public, max-age=604800, immutable`，可缓存7天；资料 JSON 使用固定 datasetVersion 和 force-cache。浏览器清理缓存或无痕会话结束后可能重新下载。

浏览器验证覆盖中国黄色、再次访问资料和成品图片0字节传输、没有运行时配色素材请求，以及外部字体挂起时仍能显示图片。外部字体采用非阻塞加载。导航分隔线已改为居中长实线。

## 跨建筑解锁条件（2026-10-26）

上游绘图节点的 link_id 不是完整研究依赖表：火枪手、手推炮、炮舰和化学本身均可为 null。详情由 `techTreeRelations` 单独补充经游戏“化学”中文说明核对的跨建筑条件：单位5/36/420及炮塔科技64需要化学47，炮塔建筑236需要炮塔科技64。沿已有升级父链继承解锁条件，保留原始绘图坐标与升级连线。不得把“所有火药单位”统一判为需要化学，例如土耳其亲兵不加此条件。波希米亚读取本民族节点时代，土耳其提示化学免费获得。

页面称“已收录的额外解锁条件”，不宣称当前导出包含全部游戏前置条件；后续新增依赖需逐项核对。14项Node测试和浏览器点击化学跳转覆盖该修正。

## 透明素材细碎像素修复（2026-10-26）

`tools/build-transparent-portraits.py` 在保留主体与分离装备后，清除8连通面积不超过20像素的孤立色块，解决浅底上的黑色脏点；不削去主体边缘。重新构建148张透明轮廓和149张固定配色成品，`portraitAssetVersion=185872-fixed2`。每张成品的透明度仍与轮廓逐像素一致。浏览器本地/线上检查含完整148张浅底总览。

复查时发现523号格鲁吉亚骑兵图另有一块106像素孤立残片，已对该素材采用128像素阈值单独清理。仅523号固定配色图使用`185872-fixed3`刷新浏览器缓存，其余素材维持`185872-fixed2`，避免全量重下。

印加编号97长矛兵图还有贴着矛杆/衣甲的黑色毛刺，普通连通域清理无法覆盖。仅对该图进行3×3轮廓开运算，并清除面积不超过20像素且接触透明边界的近黑色簇；轮廓内部的阴影保留。只对印加97号成品用`185872-fixed4`刷新缓存，其他素材版本不变。浏览器检查包含印加图解码和截图。

在浅底上逐批目视复查148张透明肖像，另对较细的羽毛、绳索、兵器和兽毛制作前后对照。构建器现在对全部图应用3×3轮廓开运算，以及仅触及透明边界、面积不超过20像素的近黑色簇清理。主体内部阴影不做去黑，原5张人工轮廓和523号106像素残片处理仍保留。所有固定配色图重建后统一用`185872-fixed5`刷新缓存；149张成品的alpha逐像素与新的透明轮廓一致。
