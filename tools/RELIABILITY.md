# 稳定性与运维

## 进程与请求

- `aoe2de.service`：网站、榜单和实时 WebSocket，监听 `127.0.0.1:3000`。
- `aoe2-background.service`：共享上游网关、公开录像任务和自动结束摘要，监听 `127.0.0.1:3001`。两个进程独立重启，各自设置 1.5 GiB 内存上限。
- Yo 的指令监听为正式 `douyu-command-listener.service`；1029928 仍仅处理指令，不发送自动通知。两者均开机启动。
- 网页的实时对局事件先原子写入 `.cache/danmaku/events/`，后台服务再消费；保留原有开局/结束去重和结束失败后 10 秒重试一次的规则。过期超过两分钟的开局通知不补发，结束跟踪继续。
- 页面错误通过统一异常处理返回 400/500，不泄露异常细节。静态文件校验目录边界及符号链接。

## 上游与录像

- 对局数据、天梯、官方录像和 Steam 头像资料查询通过后台网关统一调度。其他媒体源保留其原有独立调度。
- Companion 请求间隔至少 3 秒，同主机单并发；10 秒内重复 JSON 请求合并并缓存。自动摘要优先，队列为高优先级调用预留位置。一个读者取消不会中断其他读者共用的请求，所有读者取消后才停止。
- 429 读取 `Retry-After`，整站该主机冷却；无该头时冷却 60 秒。没有隐式重试，不通过更换 IP 绕过上游限制。
- 本机健康接口包含真实上游请求数、缓存命中、合并、429、失败、排队及并发计数。计数从后台进程启动时开始。
- 公开录像分析提交返回 202 和任务编号，浏览器每两秒查询进度；轮询不扣除每 IP 每分钟 2 次/每小时 10 次的任务提交额度。缓存结果到期或后台重启后可显式重新提交。
- 原始录像下载流式转发，已知长度及实际流均限制 64 MiB。公开录像任务最多一个，自动摘要使用另一个分析槽位。

## 访问限制

- API 配额持久化到 `.cache/api-limits.json`，IP 以 SHA-256 摘要保存；重启网站前刷新状态。
- 公开录像提交/下载共用每 IP 2 次/分钟、10 次/小时，全站最多 12 次/分钟、120 次/小时。超限给出中文提示和 `Retry-After`。
- Nginx 的 `/api/` 增加每 IP 5 请求/秒、突发 40 请求及 10 并发连接限制，超限返回 429 提示。规则样例在 `tools/nginx/aoe2-resource-limits.conf`。
- 玩家及头像资料接口也拦截自动客户端标识。UA 和自定义头不是身份认证，不能保证识别所有伪装爬虫；额度和资源上限才是兜底。

## 备份与恢复

- `aoe2-site-backup.timer` 每天北京时间 03:20 后两分钟内启动，保留最近 7 份。
- 备份目录 `/var/backups/aoe2de-cn` 权限 700，归档 600；包含代码、资源、玩家配置、当前玩家索引、反馈/统计状态、登录会话及弹幕去重状态。生成的录像缓存、浏览器二进制和依赖不备份。
- 每份归档写入 SHA-256 清单并立即校验，不发布校验失败的归档。已做实际临时目录恢复及玩家 SQLite 索引完整性检查。
- 验证：`sudo python3 /usr/local/libexec/aoe2-backup.py --verify /var/backups/aoe2de-cn/归档.tar.gz`。
- 恢复只能解压到新建的私有临时目录，确认清单后再停服务迁移；恢复 `.cache` 的属主为 `aoe2` 并保留登录文件 600、目录 700；服务文件重新安装自 `tools/systemd/`，依赖按 requirements/package-lock 安装。
- 这是同机备份，不能覆盖整台服务器或磁盘丢失；异地备份仍需另行配置目标和凭据。TLS 证书及系统镜像由主机层另外管理。

## 健康与告警

- `aoe2-site-health.timer` 每分钟检查网站/后台、两个指令服务、Nginx、公网 HTTPS 和至少 1 GiB 的磁盘余量。
- 检查或备份失败时 systemd 标记失败，并由 `aoe2-site-alert@.service` 写入 `aoe2-alert` 错误日志；未配置外部消息推送。
- 查看：`systemctl --failed`、`journalctl -t aoe2-alert`、`journalctl -u aoe2-site-health.service`。
- 后台日志：`journalctl -u aoe2-background.service`。本机完整健康信息：`curl http://127.0.0.1:3000/api/internal/health`。
- 线上回归只用无效 ID、缓存录像及模拟数据，不向直播间发送测试弹幕。

## 缓存策略（2026-10-25）

- 对局详情：实时或胜负未完整时 10 秒，已结束且全员胜负完整时网关缓存 1 小时。玩家基础资料 60 秒；列表及其他 JSON 默认 10 秒。上游冷却期间仍允许命中新鲜缓存，不使用过期实时数据冒充当前状态。
- 录像分析：v7 缓存中，胜负完整的结果保留 7 天，其他结果 30 分钟；旧 v6 缓存继续按 30 分钟读取。结果文件附带独立策略元数据，按版本隔离。最多 512 条、压缩结果合计 1 GiB，启动后、每分钟及写入后检查并淘汰过期/最旧条目。预算不含少量元数据，分析过程中允许临时占用。
- 公开分析和自动摘要共享进行中的分析及对局资料查询，按比赛与玩家去重；不同玩家视角保留不同结果。公开与自动请求仍保留各自的上游优先级。
- 个人统计、直播选手统计、小号资料、玩家历史四类内存缓存分别最多 512 条，按最近访问顺序淘汰。淘汰内存不删除持久资料；原有有效期不变。
- 头像仍每 24 小时更新。过期且已有图片时立即返回旧图，后台合并刷新；首次获取失败冷却 5 分钟。旧哈希图片从被替换时开始至少保留 24 小时，再清理无人引用的文件。
- 本机健康接口包含玩家缓存命中/未命中/淘汰、头像更新/失败/旧图命中、录像命中/合并/磁盘占用。内存 Map 的命中代表找到条目，有效期由各业务层另行判断；磁盘占用为最近一次清理快照。

## 地图种子（2026-10-25）

- 页面地图种子使用录像大厅字段 map_seed，不再显示 Replay.random_seed（随机状态）。服务器分析与浏览器本地文件解析使用 public/replay-map-seed.js 同一读取逻辑。
- 当前校验支持 DE 录像主版本 66、67、68：匹配已独立解析的大厅设置，验证聊天消息长度、终止符及尾部结构后读取有符号 32 位种子。格式不支持、结果不唯一或字段校验失败时显示“未记录”。不按用户给出的种子搜索或硬编码。
- 515704975 的原始录像已核对，地图种子为 1355428952；该局缓存已回填，原 random_seed=15774 保持原始含义。其他历史缓存缺少 mapSeed 时显示“未记录”，新分析会提取正确字段。

## 入口与登录加固（2026-10-25）

- SSH 使用 tools/ssh/00-aoe2cn-hardening.conf：仅公钥登录，root 保留公钥访问；关闭密码、键盘交互及空密码。每连接最多 3 次验证，登录等待 30 秒。部署时先建立定时回滚，重新验证一条密钥登录连接后撤销回滚；不要在未验证密钥时复制覆盖。
- Nginx HTTPS server 引入 /etc/nginx/snippets/aoe2-security.conf，对应 tools/nginx/aoe2-security.conf：隐藏文件、源码目录、私有接口和常见漏洞入口直接 404；保留 .well-known/ACME。仅支持 GET/HEAD/POST，拒绝其他 Host。关闭版本号，TLS 仅 1.2/1.3；HSTS 先设一天、不含子域和 preload。CSP 只限制 base-uri/object-src/frame-ancestors，保留现有脚本和外部资源兼容。
- Fail2ban 使用 tools/fail2ban 两个配置，需安装 fail2ban/nftables。sshd 为 systemd 后端，10 分钟 5 次失败；明确的 Web 敏感路径扫描 1 分钟 8 次，仅封 80/443。封禁从 1 小时开始递增，最长一天。普通 404、机器人正常索引和 API 429 不作为扫描封禁依据。过滤器已在真实日志上离线验证，防火墙动作使用文档测试 IP 验证后解除。
- .cache、登录会话、.git 和 .codex-tmp 收紧访问权限；应用 staticFilePath 也拒绝隐藏文件，避免误放到 public/ 后被直接下载。
- 无缓存的录像页面需要点击“开始分析”，不再因爬虫只渲染页面而自动创建解析任务；缓存仍自动显示。主动伪造浏览器头并 POST 的脚本仍受配额和并发约束，不能仅靠浏览器标识保证识别所有自动客户端。
- 健康巡检加入 fail2ban.service；查看封禁使用 fail2ban-client status sshd / aoe2-scanner，误封解除用 fail2ban-client set 对应jail unbanip 对应IP。
- /var/backups 仍为同机备份，告警仍为本机日志；本次不改变已有备份范围和通知渠道。
